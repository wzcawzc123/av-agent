# AV Agent 功能说明书

> 版本：1.2.0　|　适用仓库：wzcawzc123/av-agent（私有）　|　最后更新：2026-09-06

## 1. 产品概述

AV Agent 是为音视频行业售前技术工程师打造的对话式方案生成工具。工程师在手机上用自然语言描述项目需求（如"100 平会议室音响方案"），Agent 自动澄清缺失信息、确认需求，然后依托**公司产品库**与**常规配置模板**，由大模型做语义适配，自动生成交付文件：

- 文字设计方案（Word）
- 偏离表（Excel）
- 演示 PPT（PPTX）
- PDF 版方案（需电脑安装 LibreOffice）

系统以局域网 Web 服务方式运行在电脑端，手机浏览器即可控制使用，无需安装 App；也可打包为 Windows exe 直接分发。

## 2. 核心功能

| 功能 | 说明 |
|---|---|
| 对话式需求采集 | 解析面积、场景、预算、品牌偏好、交付物类型；缺失字段自动追问 |
| 需求确认 | 信息齐全后汇总展示，用户确认后再生成，避免返工 |
| 产品库管理 | 手机端 📦 页面上传公司产品 Excel（名称/型号/参数/底价/市场价/分类），自动入库与按型号去重更新，并展示产品列表 |
| 模板库管理 | 手机端 🗂️ 页面注册文字方案模板、PPT 母版、偏离表模板；按面积注册常规配置模板（100/200/300 平），生成时自动匹配 |
| 大模型适配 | 可插拔 Provider：内置 13 家主流提供商（OpenAI/Anthropic/阿里百炼/DeepSeek/Kimi/MiMo/MiniMax/阶跃星辰/硅基流动/OpenRouter/智谱/文心/Gemini），支持自定义新增 OpenAI 兼容/Anthropic/Gemini 提供商，模板 + 产品库 + 需求语义适配出设备清单，自动回填底价/市场价 |
| 文档生成 | Word 方案、偏离表 Excel、PPT 三件套异步生成，SSE 实时进度，生成完可直接下载 |
| 清单编辑（BOM） | 项目文件页打开清单编辑器，增删行、改数量/单价/备注，小计实时计算，一键重出 Excel 报价表；单价为 0 的行自动标注「待询价」 |
| 清单存为模板 | 编辑后的清单一键存入模板库（config 类型），按面积/场景自动匹配复用 |
| 模板文件上传 | 手机端上传 docx/pptx 模板文件注册，无需命令行 |
| 产品改价 | 产品库每项可改底价/市场价，方案生成时自动回填最新价格 |
| PDF 转换 | 通过 LibreOffice headless 将 Word 转为 PDF |
| 访问鉴权 | 所有 API 需携带访问口令（X-Access-Token 请求头），防局域网内未授权访问 |
| exe 分发 | PyInstaller 打包为单文件 Windows exe，原生桌面窗口（PyWebView）+ 系统托盘常驻，免装 Python 环境 |
| 专业工具箱 | 四个独立引擎直通对话：**会议系统**（按面积/场景推导设备清单）、**公共广播**（分区×型号×数量 → 功率计算 → 功放档位推荐）、**LED 屏**（点数/单元板排布计算）、**偏离表**（按招标清单逐项生成偏离说明 Excel），无需模型配置即可用 |
| 引擎注册表 | 全部引擎经统一 `register_engine()` 注册（意图识别 / 执行 / 摘要统一挂载），新增引擎只需一行注册，无重复维护 |
| 知识库（RAG-lite） | 上传公司文档/规范进知识库，对话意图解析时自动检索 top3 相关片段注入模型提示词，答案更贴合内部资料 |
| 安全加固 | API Key 等敏感配置磁盘加密存储（Fernet 派生密钥）；访问口令校验防 XFF 头伪造绕过；前端密钥掩码显示 |
| 更新检查 | 内置 GitHub Releases 版本比较，设置页可查最新版本与更新说明 |

## 3. 系统架构

```
手机浏览器 (单页前端 static/：聊天 / 产品库 / 模板库 / 设置)
      │  HTTP + SSE
      ▼
FastAPI 应用 (app/main.py)
  ├── app/api/            REST 端点：chat / projects / generate / data / settings
  ├── app/orchestrator/   对话状态机、意图识别、澄清追问、需求确认
  ├── app/llm/            模型 Provider 适配层（可插拔）+ 模板适配
  ├── app/generators/     Word / Excel / PPT 生成 + PDF 转换 + 生成管线
  ├── app/tasks/          异步任务队列 + SSE 进度订阅
  ├── app/db/             SQLite（SQLAlchemy）、产品导入、模板存储
  └── app/security/       访问口令校验、密钥工具（Fernet 框架）
```

## 4. 对话与生成工作流

```
用户输入 → 意图识别(LLM) → 缺字段？→ 是：追问 → 循环采集
                          → 否：需求汇总 → 用户确认
                                        → 提交生成任务
                                        → 匹配常规配置模板（按面积）
                                        → LLM 适配设备清单（结合产品库）
                                        → 生成 Word / 偏离表 / PPT（异步 + SSE 进度）
                                        → 可选 PDF 转换 → 输出下载链接
```

要点：

- 对话状态按 `project_id` 保存在服务内存中（当前版本不跨进程持久化）。
- 需求槽位：`area`（面积）、`scene`（场景）、`budget`（预算）、`brand`（品牌）、`deliverables`（交付物列表：`doc`/`deviation`/`ppt`/`pdf`）。
- 设备清单适配结果强校验：每项必须有 `type` 与 `qty`，缺少时自动补 `spec`/`model`/`base_price`/`market_price`。
- 价格回填规则：设备未带价格时，先用 `spec` 关键词匹配产品库名称+型号；匹配不到再用 `type`；再兜底匹配 spec 前两个字符。

### 7.2 自定义新增提供商

参考 ETA-2 的 Provider 体系实现，支持三类协议：

- **OpenAI 兼容**（默认）：填名称 + Base URL + API Key + 模型列表（逗号分隔），调用 `{base}/chat/completions`；
- **Anthropic**：调用 `{base}/v1/messages`（Messages API，x-api-key 鉴权）；
- **Gemini**：调用 `generativelanguage.googleapis.com/v1beta`（generateContent）。

支持能力：

- 增删改查：内置不可删、可复制为自定义、可重置（保留已填 API Key）；
- **远程拉取模型**：GET `{base}/models`（Anthropic 为 `{base}/v1/models`），一键同步模型列表；
- **连接测试**：发送最小请求验证 API Key 与 Base URL；
- **来源归一化**：自定义 Base URL 命中已知域名（如 api.deepseek.com、api.xiaomimimo.com）时自动识别为对应来源，否则归为 custom；
- 持久化：`data/providers.json`（内置首次启动自动合并），当前选择存 `data/model.json`。

## 8. 产品 Excel 约定

表头（列顺序不限，按表头名匹配）：

```
产品名称 | 型号 | 参数 | 底价 | 市场价 | 分类
```

- `型号` 列为唯一键：同型号重复上传时更新旧记录，否则新增。
- 兼容旧表头 `低价`（同样映射到底价字段）。
- 返回 `{"inserted": n, "updated": m}`。

## 8.5 产品库导入

支持直接导入厂商产品清单 Excel（多 sheet 自动识别）：

- 支持格式：MAXHUB 全产品清单（分类段 + 名称继承）、音视频报价清单（标题行 + 分类段）等常见表格；
- 字段映射：产品名称 / 型号（或销售型号、产品型号(新)）/ 品牌 / 产品描述 / 尺寸 / 视距 / 适用范围等；
- 去重规则：型号唯一，重复型号自动跳过，**不覆盖**已有产品；
- 价格策略：导入时价格留空（0），后续单独导入带底价/市场价的清单，或在方案生成后人工填写；
- 分类体系：`sheet名/分类段`（如 `会议平板/标准款`、`专业拾扩音/扩声系统`）；
- 兼容旧库：自动迁移（`low_price` → `base_price`，缺失列自动补齐），旧数据无损。

CLI 批量导入：

```bash
python scripts/import_products_cli.py "产品清单A.xlsx" "产品清单B.xlsx"
```

Web 端：设置页上传 Excel 即可导入（/api/products）。

## 10. 打包为 Windows exe

仓库内置 PyInstaller 打包配置：

| 文件 | 作用 |
|---|---|
| `exe_entry.py` | 打包入口：启动 uvicorn、持久化访问口令到 `data/access_token.txt`（重启不变）、PyWebView 原生窗口、pystray 托盘（关窗最小化到托盘、端口被占自动避让）、缺桌面依赖时退回浏览器模式 |
| `av-agent.spec` | PyInstaller 配置：收集 uvicorn/sqlalchemy/httpx/openpyxl/docx/pptx/cryptography 等子模块，打包 `static/` |
| `build_exe.bat` | Windows 一键打包：装依赖 → 运行 PyInstaller → 产出 `dist\AVAgent.exe` |

exe 运行机制：数据目录（`data/`、`output/`、`uploads/`）创建在 exe 同级目录；静态资源解压在 PyInstaller 临时目录（`_MEIPASS`）；访问口令首次生成后持久化，环境变量 `AV_ACCESS_TOKEN` 优先。桌面模式依赖 `pywebview`（原生窗口）与 `pystray`（托盘），由 `build_exe.bat` 额外安装；PyInstaller 通过 `collect_data_files("webview")` 收集 WebView2Loader 等资源。**打包需在 Windows 上执行**（PyInstaller 不支持跨平台编译 Windows exe）。

## 12. 已知边界与限制

- 对话槽位与运行中任务保存在服务内存，重启服务后需重新发起对话。
- 生成 PDF 依赖电脑端安装 LibreOffice，且需先生成 Word。
- 模板库注册的是文件路径（文件本身需自行放到服务器可读位置），Word 模板正文占位符为 `{{项目名称}}`、`{{方案正文}}`。
- `data/model.json` 当前为明文存储（加密密钥框架已就绪，后续版本接入）。
- 产品库导入与生成涉及大模型调用，需要网络可访问对应模型 API。
- exe 打包需在 Windows 上执行，当前仓库为源码 + 打包配置，不含预编译 exe 产物。

  优先取 `.exe` 资产的下载地址。

## 15. 企业架构（v3.0）

> 总体链路：`用户 → API → Planner → Agents → Knowledge / Database → Documents`。
> v3.0 不替换既有「对话澄清 → 确认 → 生成」链路，而是把**生成阶段**重构为计划驱动的
> Agent 工作流；旧接口 `/api/generate`、SSE 任务事件与前端完全不变（向后兼容，见 15.7）。

### 15.1 模块与职责

| 模块 | 职责 |
|---|---|
| `app/planner/planner.py` | `PlanStep(name, agent, params, depends_on)`、`Plan(steps)`（`to_json/from_json`）、`Planner.create_plan(requirement, deliverables) -> Plan`。纯确定性，不调 LLM |
| `app/agents/base_agent.py` | `BaseAgent`：`name/description/depends_on` 类属性 + `analyze(context)`（默认 pass）/ `execute(context)`（默认抛 NotImplementedError）/ `validate(context)`（默认 True） |
| `app/agents/registry.py` | `AGENT_REGISTRY`、`register(name, cls)`、`get_agent(name)`（未知抛 KeyError 带可用列表）、`list_agents()`；具体 Agent 模块导入时自动注册 |
| `app/agents/*.py` | 6 个具体 Agent（文件名即注册名）：`requirement_analysis`（槽位规范化 + `infer_systems`）、`product_selection`（`compose_devices` + `find_config_template`，产出 `context.devices` 并写项目记忆）、`solution_design`（`build_doc_from_llm` + `find_doc_template`，产出 `files["doc"]`，仅 deliverables 含 doc 时执行）、`bom_generation`（`build_design_sheet` 出 Excel，写 `Project.bom_json`）、`quotation`（统计总价/待询价，写 `Quotation` 行）、`document_generation`（ppt → `build_ppt`；pdf → `convert_docx_to_pdf`；deviation → `generate_deviation_sheet`，产出 `files["pdf"/"ppt"/"deviation"]`） |
| `app/workflow/workflow.py` | `WorkflowContext(project_id, slots, cfg, session, ...)` 共享上下文；`SalesWorkflow.run(context, progress_cb=None)` 顺序执行计划、尊重 `depends_on`（缺失依赖跳过并记 skipped 日志）、步骤级错误隔离（异常写 `context.errors[step]` 继续）、按步骤均分 0-100 进度回调、结束更新 `WorkflowRun`（status/progress/result_json） |
| `app/db/models.py` | v3.0 企业表：`Organization / User / KnowledgeDocument / Solution / Quotation / WorkflowRun / AgentExecutionLog`；`Project` 扩展 `org_id / customer_name / memory_json` |
| `app/db/memory.py` | 项目记忆：`remember(session, project_id, key, value)`（合并写 `Project.memory_json`）、`recall(session, project_id, key=None)` |
| `app/knowledge/retriever.py` | 知识库：`register_document / list_documents / delete_document / retrieve(query, top_k)`，纯 Python 关键词打分（title/excerpt/meta），无需向量库 |
| `app/api/routes_workflow.py` | v3.0 API：提交工作流运行、运行列表/详情/日志、组织、知识库 |
| `app/tasks/queue.py` | v3.0 起 `_run` 改由 `Planner.create_plan` + `SalesWorkflow.run` 驱动；`submit_task / get_task / subscribe / SSE` 事件格式不变 |

### 15.2 计划生成规则（Planner）

- 恒有 `requirement_analysis`、`product_selection` 两步；
- deliverables 含 `doc` 或 `ppt` → 追加 `solution_design`（`depends_on=["product_selection"]`）；
- deliverables 含 `excel` 或为空（默认 excel）→ 追加 `bom_generation`（`depends_on=["product_selection"]`）+ `quotation`（`depends_on=["bom_generation"]`）；
- deliverables 含 `ppt/pdf/deviation` → 追加 `document_generation`（deliverables 含 doc/ppt 时 `depends_on=["solution_design"]`，否则 `depends_on=["bom_generation"]`）；
- 步骤顺序：`requirement_analysis → product_selection → solution_design → bom_generation → quotation → document_generation`；`step.name == step.agent`。

### 15.3 执行流程（SalesWorkflow）

```
POST /api/workflow/runs {project_id}
  → 读 Project.requirement_json 恢复 slots；deliverables 缺省 ["excel"]
  → 建 WorkflowRun(status=pending)；组装 cfg{deliverables, project_dir, run_id}
  → submit_task(project_id, cfg, slots) → {run_id, task_id}
后台 _run：
  → load_model_config → get_provider
  → plan = Planner.create_plan(slots, cfg.deliverables)
  → ctx = WorkflowContext(project_id, slots, cfg, session, provider, plan)
  → result = await SalesWorkflow.run(ctx, cb)   # cb(p, m) 转发 t.progress/message + _notify
  → 成功写 Project.bom_json
  → done 事件（与旧 /api/generate 一致）
每步：get_agent(step.agent) → analyze → execute → validate
  → 写 AgentExecutionLog（success/failed/skipped，detail_json 存产出摘要，error 存异常字符串）
  → 异常隔离：context.errors[step] = str(e)，继续后续步骤
返回：{"files": context.files, "errors": context.errors, "bom": context.bom}
```

### 15.4 Agent 上下文约定

- 统一从 `context` 取：`context.slots / context.session / context.provider / context.cfg / context.project_id`；
- 统一写：`context.outputs[name]`（本步产出）、`context.files`（生成文件路径，key 与 `generators/pipeline.py` 一致：`doc/pdf/excel/ppt/deviation`）、`context.bom`、`context.errors`（key 为步骤名）；
- **Agent 不写 `WorkflowRun / AgentExecutionLog`**（由 Workflow 层统一写），可读既有表（Project/Product/Template 等）；
- AI 调用一律走 `context.provider.chat` + `app/llm/prompts.py` 常量。

### 15.5 企业数据模型

| 表 | 说明 |
|---|---|
| `organizations` | 组织（多租户维度），`code` 唯一 |
| `users` | 组织内用户，`username` 唯一可空 |
| `knowledge_documents` | 知识库条目：标题/类型/路径/摘要/元数据（JSON 字符串）/所属组织 |
| `solutions` | 方案：内容 JSON + 文件路径 JSON + 状态 |
| `quotations` | 报价：`total_amount`（Float）+ 分项 JSON + 状态 |
| `workflow_runs` | 一次工作流运行：计划 JSON、状态、进度（Float）、结果 JSON、错误 |
| `agent_execution_logs` | 运行内单步骤日志：step、agent_name、status（success/failed/skipped）、detail_json、error、起止时间 |
| `projects` | 扩展 `org_id`（可空）、`customer_name`、`memory_json`（Project Memory，JSON 字符串） |

所有新增表沿用现有风格：`Mapped / mapped_column`、`datetime.utcnow` 默认、JSON 字段以 Text 存 JSON 字符串；
`Base.metadata.create_all` 自动建新表，既有 SQLite 库无需迁移即可启动（PG 环境同样由 create_all 建表）。

### 15.6 知识库与项目记忆

- **知识库**：`register_document(session, title, doc_type, file_path, excerpt="", meta=None) -> int`；
  `list_documents(session) -> list[dict]`；`delete_document(session, doc_id) -> bool`；
  `retrieve(session, query, top_k=5) -> list[dict]`：对 title/excerpt/meta 做关键词打分，纯 Python 实现；
- **项目记忆**：`remember(session, project_id, key, value)` 以 key 合并写 `Project.memory_json`
  （同 key 覆盖、不丢其它 key）；`recall(session, project_id, key=None)` 返回整个记忆 dict（key 缺省）或指定值。

### 15.7 部署与向后兼容

- **部署**：仓库根 `docker-compose.yml` 提供 `postgres:16-alpine` + `redis:7-alpine`
  （带 volume 与 healthcheck）；环境变量 `AV_DATABASE_URL`（PG URL）、`AV_REDIS_URL`、`AV_ENV=prod`
  切换，未设置时沿用内置 SQLite，行为不变；
- **向后兼容**：`/api/generate`、`/api/tasks/{task_id}` 与 SSE 事件（`progress`/`done`）、
  `/api/generate` 的 422 门控、`task_id` 返回结构完全不变；`generate_deliverables` 保留
  （测试仍覆盖），供旧链路使用；v3.0 工作流为新增并行入口。


## 16. v1.2.0 增强说明

### 16.1 引擎注册表

过去四个引擎（会议 / 广播 / LED / 偏离表）的识别关键词、执行函数、摘要函数分散在三处维护，新增引擎容易出现「能识别但执行不到」的洞。v1.2.0 统一为注册表模式：

```python
register_engine(
    name="broadcast",
    display="公共广播",
    keywords=("广播", "功放", ...),
    run=run_broadcast,      # 执行函数
    summarize=summarize,    # 结果摘要（用于聊天回复）
)
```

- 意图识别、执行分发、摘要展示全部从注册表读取，目录单一；
- 新增引擎 = 一个 `register_engine()` 调用 + 业务函数，无需改动分发代码；
- 对话直通 `POST /api/chat`（命中关键词即执行，不依赖模型配置），也保留独立端点 `POST /api/engines/{name}` 供前端工具箱调用。

### 16.2 知识库接入意图解析（RAG-lite）

知识库此前只有 CRUD 与检索接口，未接入生成流程。v1.2.0 将其接入通用对话链路：

- 用户输入 → 关键词检索知识库（title/excerpt/meta 打分，纯 Python 无向量库依赖）→ 取 top3 片段 → 注入意图解析提示词「参考文档」段；
- 效果：内部规范、历史方案摘要被模型引用，意图解析与后续生成更贴合公司资料；
- 检索失败不阻断主流程（静默降级为不带上下文）。

### 16.3 广播引擎功能细节

- 输入：自然语言多分区描述，如「广播系统 1F大厅 24只T-601 12只T-105」或「2F办公区 8只T-601，3F走廊 6只T-105」；
- 解析：按「数量+型号」识别每分区扬声器清单；分区名可含楼层前缀（如 `1F大厅`，v1.2.0 修复了此前将 `1F` 楼层前缀误解析为型号的缺陷）；
- 计算：每分区按型号额定功率累加 ×1.5 余量 → 汇总总功率 → 查功放档位表推荐功放型号；
- 输出：分区分项功率 + 推荐功放 + Excel 设备清单下载。

### 16.4 安全加固

- **密钥落盘加密**：`providers.json` 与 `model.json` 中的 API Key 以 `enc:` 前缀 + Fernet 密文存储；密钥文件缺失时自动生成并用系统权限保护；
- **XFF 防绕过**：访问口令中间件改为「直接读取对端地址校验」，不再信任 `X-Forwarded-For` 头，防止局域网内伪造来源绕过鉴权；
- **前端掩码**：设置页 API Key 回显仅显示首尾（如 `sk-s***ced`），不泄露完整密钥。
