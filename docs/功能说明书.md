# AV Agent 功能说明书

> 版本：1.0.2　|　适用仓库：wzcawzc123/av-agent（私有）　|　最后更新：见 git 提交记录

## 1. 产品概述

AV Agent 是为音视频行业售前技术工程师打造的对话式方案生成工具。工程师在手机上用自然语言描述项目需求（如"100 平会议室音响方案"），Agent 自动澄清缺失信息、确认需求，然后依托**公司产品库**与**常规配置模板**，由大模型做语义适配，自动生成交付文件：

- 文字设计方案（Word）
- 偏离表（Excel）
- 演示 PPT（PPTX）
- PDF 版方案（需电脑安装 LibreOffice）

系统以局域网 Web 服务方式运行在电脑端，手机浏览器即可控制使用，无需安装 App；也可打包为 Windows exe 直接分发。

## 2. 核心功能

| 功能 | 说明 |
|---|---|
| 对话式需求采集 | 解析面积、场景、预算、品牌偏好、交付物类型；缺失字段自动追问 |
| 需求确认 | 信息齐全后汇总展示，用户确认后再生成，避免返工 |
| 产品库管理 | 手机端 📦 页面上传公司产品 Excel（名称/型号/参数/底价/市场价/分类），自动入库与按型号去重更新，并展示产品列表 |
| 模板库管理 | 手机端 🗂️ 页面注册文字方案模板、PPT 母版、偏离表模板；按面积注册常规配置模板（100/200/300 平），生成时自动匹配 |
| 大模型适配 | 可插拔 Provider：内置 13 家主流提供商（OpenAI/Anthropic/阿里百炼/DeepSeek/Kimi/MiMo/MiniMax/阶跃星辰/硅基流动/OpenRouter/智谱/文心/Gemini），支持自定义新增 OpenAI 兼容/Anthropic/Gemini 提供商，模板 + 产品库 + 需求语义适配出设备清单，自动回填底价/市场价 |
| 文档生成 | Word 方案、偏离表 Excel、PPT 三件套异步生成，SSE 实时进度，生成完可直接下载 |
| PDF 转换 | 通过 LibreOffice headless 将 Word 转为 PDF |
| 访问鉴权 | 所有 API 需携带访问口令（X-Access-Token 请求头），防局域网内未授权访问 |
| exe 分发 | PyInstaller 打包为单文件 Windows exe，原生桌面窗口（PyWebView）+ 系统托盘常驻，免装 Python 环境 |

## 3. 系统架构

```
手机浏览器 (单页前端 static/：聊天 / 产品库 / 模板库 / 设置)
      │  HTTP + SSE
      ▼
FastAPI 应用 (app/main.py)
  ├── app/api/            REST 端点：chat / projects / generate / data / settings
  ├── app/orchestrator/   对话状态机、意图识别、澄清追问、需求确认
  ├── app/llm/            模型 Provider 适配层（可插拔）+ 模板适配
  ├── app/generators/     Word / Excel / PPT 生成 + PDF 转换 + 生成管线
  ├── app/tasks/          异步任务队列 + SSE 进度订阅
  ├── app/db/             SQLite（SQLAlchemy）、产品导入、模板存储
  └── app/security/       访问口令校验、密钥工具（Fernet 框架）
```

| 模块 | 职责 |
|---|---|
| `app/api/routes_chat.py` | 对话入口：维护每个项目（project_id）的会话状态与已采集槽位；未配置模型时返回引导提示 |
| `app/api/routes_generate.py` | 提交生成任务、查询任务状态、SSE 进度流、文件下载（仅限输出目录内） |
| `app/api/routes_data.py` | 产品 Excel 上传导入、产品列表、模板注册/列表/删除（含常规配置模板按面积管理） |
| `app/api/routes_settings.py` | 读取/保存模型配置（provider/api_key/model/base_url） |
| `app/api/routes_projects.py` | 项目创建、列表、详情 |
| `app/orchestrator/state_machine.py` | 状态机：IDLE → COLLECTING → CONFIRMING → GENERATING → DELIVERED |
| `app/orchestrator/intent.py` | 调用大模型从用户语句提取结构化需求 JSON，带 JSON 提取与容错 |
| `app/orchestrator/clarify.py` | 按固定顺序追问缺失字段（面积→场景→预算→品牌→交付物） |
| `app/orchestrator/confirm.py` | 汇总槽位生成确认文案 |
| `app/llm/provider_store.py` | 提供商体系：内置 13 家（含 MiMo）+ 官方模型目录 + 来源注册（按 URL 反查）+ 增删改查/复制/重置/远程拉模型（参考 ETA-2 Provider 体系），持久化到 `data/providers.json` |
| `app/llm/registry.py` | 客户端工厂：按 provider_type（openai_compatible/anthropic/gemini）与 endpoint_mode 分派，模型配置持久化到 `data/model.json` |
| `app/llm/providers/` | OpenAI 兼容 / Anthropic（Messages API）/ Gemini 三种客户端实现 |
| `app/llm/adapt.py` | 大模型语义适配：常规模板 + 产品库 + 需求 → 设备清单；价格缺失时按关键词回填产品库价格 |
| `app/generators/pipeline.py` | 生成管线编排：匹配配置模板 → 适配设备清单 → 逐项产出交付物 |
| `app/tasks/queue.py` | 内存任务队列，后台协程执行，按 project_id 广播进度事件 |

## 4. 对话与生成工作流

```
用户输入 → 意图识别(LLM) → 缺字段？→ 是：追问 → 循环采集
                          → 否：需求汇总 → 用户确认
                                        → 提交生成任务
                                        → 匹配常规配置模板（按面积）
                                        → LLM 适配设备清单（结合产品库）
                                        → 生成 Word / 偏离表 / PPT（异步 + SSE 进度）
                                        → 可选 PDF 转换 → 输出下载链接
```

要点：

- 对话状态按 `project_id` 保存在服务内存中（当前版本不跨进程持久化）。
- 需求槽位：`area`（面积）、`scene`（场景）、`budget`（预算）、`brand`（品牌）、`deliverables`（交付物列表：`doc`/`deviation`/`ppt`/`pdf`）。
- 设备清单适配结果强校验：每项必须有 `type` 与 `qty`，缺少时自动补 `spec`/`model`/`base_price`/`market_price`。
- 价格回填规则：设备未带价格时，先用 `spec` 关键词匹配产品库名称+型号；匹配不到再用 `type`；再兜底匹配 spec 前两个字符。

## 5. 数据模型（SQLite）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `products` | name, model(唯一), params_json, base_price, market_price, category | 公司产品库；按型号去重，重复上传为更新 |
| `templates` | name, type, file_path, description, version | 文档模板注册表；type ∈ doc/ppt/deviation |
| `config_templates` | name, area, scene, config_json | 常规配置模板；按面积精确匹配，无精确值时取面积最接近者 |
| `projects` | name, requirement_json, status | 项目记录 |
| `tasks` | project_id, deliverable_type, status, progress, file_path | 生成任务记录（持久表；当前队列运行时态在内存） |
| `settings` | key, value | 通用键值设置 |

### 7.2 自定义新增提供商

参考 ETA-2 的 Provider 体系实现，支持三类协议：

- **OpenAI 兼容**（默认）：填名称 + Base URL + API Key + 模型列表（逗号分隔），调用 `{base}/chat/completions`；
- **Anthropic**：调用 `{base}/v1/messages`（Messages API，x-api-key 鉴权）；
- **Gemini**：调用 `generativelanguage.googleapis.com/v1beta`（generateContent）。

支持能力：

- 增删改查：内置不可删、可复制为自定义、可重置（保留已填 API Key）；
- **远程拉取模型**：GET `{base}/models`（Anthropic 为 `{base}/v1/models`），一键同步模型列表；
- **连接测试**：发送最小请求验证 API Key 与 Base URL；
- **来源归一化**：自定义 Base URL 命中已知域名（如 api.deepseek.com、api.xiaomimimo.com）时自动识别为对应来源，否则归为 custom；
- 持久化：`data/providers.json`（内置首次启动自动合并），当前选择存 `data/model.json`。

## 8. 产品 Excel 约定

表头（列顺序不限，按表头名匹配）：

```
产品名称 | 型号 | 参数 | 底价 | 市场价 | 分类
```

- `型号` 列为唯一键：同型号重复上传时更新旧记录，否则新增。
- 兼容旧表头 `低价`（同样映射到底价字段）。
- 返回 `{"inserted": n, "updated": m}`。

## 8.5 产品库导入

支持直接导入厂商产品清单 Excel（多 sheet 自动识别）：

- 支持格式：MAXHUB 全产品清单（分类段 + 名称继承）、音视频报价清单（标题行 + 分类段）等常见表格；
- 字段映射：产品名称 / 型号（或销售型号、产品型号(新)）/ 品牌 / 产品描述 / 尺寸 / 视距 / 适用范围等；
- 去重规则：型号唯一，重复型号自动跳过，**不覆盖**已有产品；
- 价格策略：导入时价格留空（0），后续单独导入带底价/市场价的清单，或在方案生成后人工填写；
- 分类体系：`sheet名/分类段`（如 `会议平板/标准款`、`专业拾扩音/扩声系统`）；
- 兼容旧库：自动迁移（`low_price` → `base_price`，缺失列自动补齐），旧数据无损。

CLI 批量导入：

```bash
python scripts/import_products_cli.py "产品清单A.xlsx" "产品清单B.xlsx"
```

Web 端：设置页上传 Excel 即可导入（/api/products）。

## 10. 打包为 Windows exe

仓库内置 PyInstaller 打包配置：

| 文件 | 作用 |
|---|---|
| `exe_entry.py` | 打包入口：启动 uvicorn、持久化访问口令到 `data/access_token.txt`（重启不变）、PyWebView 原生窗口、pystray 托盘（关窗最小化到托盘、端口被占自动避让）、缺桌面依赖时退回浏览器模式 |
| `av-agent.spec` | PyInstaller 配置：收集 uvicorn/sqlalchemy/httpx/openpyxl/docx/pptx/cryptography 等子模块，打包 `static/` |
| `build_exe.bat` | Windows 一键打包：装依赖 → 运行 PyInstaller → 产出 `dist\AVAgent.exe` |

exe 运行机制：数据目录（`data/`、`output/`、`uploads/`）创建在 exe 同级目录；静态资源解压在 PyInstaller 临时目录（`_MEIPASS`）；访问口令首次生成后持久化，环境变量 `AV_ACCESS_TOKEN` 优先。桌面模式依赖 `pywebview`（原生窗口）与 `pystray`（托盘），由 `build_exe.bat` 额外安装；PyInstaller 通过 `collect_data_files("webview")` 收集 WebView2Loader 等资源。**打包需在 Windows 上执行**（PyInstaller 不支持跨平台编译 Windows exe）。

## 12. 已知边界与限制

- 对话槽位与运行中任务保存在服务内存，重启服务后需重新发起对话。
- 生成 PDF 依赖电脑端安装 LibreOffice，且需先生成 Word。
- 模板库注册的是文件路径（文件本身需自行放到服务器可读位置），Word 模板正文占位符为 `{{项目名称}}`、`{{方案正文}}`。
- `data/model.json` 当前为明文存储（加密密钥框架已就绪，后续版本接入）。
- 产品库导入与生成涉及大模型调用，需要网络可访问对应模型 API。
- exe 打包需在 Windows 上执行，当前仓库为源码 + 打包配置，不含预编译 exe 产物。

## 12. 软件更新（版本与发布）

- 版本号统一由 `app/version.py` 的 `VERSION` 管理，`/api/health` 与 FastAPI
  文档标题同步输出。
- `GET /api/update/check`：请求更新检查地址（默认 GitHub Releases latest），
  比较版本号（`app.version.is_newer`，忽略前缀 v），返回
  `current_version / latest_version / has_update / notes / download_url / published_at`。
- `GET|PUT /api/update/config`：读写更新检查地址与 GitHub Token（私有仓库用），
  配置存 `data/update.json`；Token 仅用于读取 Release，不返回明文。
- 更新检查失败（网络/认证）返回 502 与具体原因，不影响主流程。
- exe 打包配置（`av-agent.spec`）已包含 `app/version.py` 与全部新模块；
  Release 资产建议上传 Windows 构建的 `AVAgent.exe`，客户端检查更新时
  优先取 `.exe` 资产的下载地址。
