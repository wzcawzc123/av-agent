# AV Agent 发布更新操作手册

> 适用版本：1.0.1+　|　仓库：`wzcawzc123/av-agent`（私有，默认分支 `main`）

本文档是**发布者**（你自己）每次推送新版本的操作手册。客户端（exe 使用者）不需要读本文档。

---

## 一、更新机制原理（30 秒理解）

```
你发布新版 Release（tag + exe 资产）
   │
   ▼
GitHub Releases API（https://api.github.com/repos/wzcawzc123/av-agent/releases/latest）
   ▲
   │ GET /api/update/check（客户端内置）
客户端「设置 → 🔄 软件更新 → 检查更新」
   │ 比较 app/version.py 的 VERSION 与 Release 的 tag_name
   ▼
有新版 → 显示版本号 / 更新说明 / exe 下载链接
```

关键约定：

- **版本号唯一来源**：`app/version.py` 的 `VERSION`（当前 `1.0.1`）。改版本只改这一处，`/api/health`、FastAPI 标题、exe 启动横幅自动同步。
- **Release tag 必须带 `v` 前缀**：如 `v1.0.1`；比较版本时会自动忽略前缀 `v`，`1.0.10 > 1.0.9` 也能正确判断。
- **exe 资产名**：`AVAgent.exe`（`build_exe.bat` 固定输出 `dist\AVAgent.exe`），更新检查会优先取 `.exe` 资产作为下载地址。

## 二、发布新版完整流程

### 第 1 步：改版本号并提交

1. 编辑 `app/version.py`，把 `VERSION = "1.0.1"` 改为新版本（如 `1.0.2`）。
2. 按需修改 `docs/` 说明书的版本号。
3. 提交并推送：

```bash
git add -A
git commit -m "release: v1.0.1"
git push origin main
```

### 第 2 步：在 Windows 上构建 exe

> ⚠️ PyInstaller 不支持交叉打包：**必须在 Windows 上构建 exe**，Mac/Linux 上都产不出 Windows exe。

1. 把仓库克隆/拉取到 Windows 电脑；
2. 双击 `build_exe.bat`（自动装依赖 + 打包，约 2-5 分钟）；
3. 产物：`dist\AVAgent.exe`。

手动等价命令：

```bat
pip install -r requirements.txt
pip install pyinstaller
pyinstaller --clean --noconfirm av-agent.spec
```

### 第 3 步：发布 Release（二选一）

**方式 A：命令行（推荐，本机已配好 gh）**

```bash
gh release create v1.0.1 dist\AVAgent.exe --title "AV Agent v1.0.1" --notes "更新说明"
```

**方式 B：GitHub 网页**

1. 打开 https://github.com/wzcawzc123/av-agent/releases → 「Draft a new release」；
2. Tag 填 `v1.0.1`，标题填版本名，写更新说明；
3. 把 `dist\AVAgent.exe` 拖入 Assets 框 → 发布。

### 第 4 步：验证

```bash
gh release view v1.0.1 -R wzcawzc123/av-agent --json tagName,assets
```

确认 `assets` 里包含 `AVAgent.exe`。然后自己在手机客户端点「检查更新」，应看到新版本 + 下载链接。

## 三、私有仓库的客户端配置（重要）

仓库是私有的，客户端直接请求 GitHub API 会 401。每个客户端需要配置一次：

1. 打开客户端「设置 → 🔄 软件更新」；
2. 生成 GitHub Token：GitHub → Settings → Developer settings → Personal access tokens → Generate new token，勾选 `repo`（只读 Release 只需 `repo` 范围）；
3. 把 Token 粘贴到「GitHub Token」输入框 → 「保存更新配置」。

Token 保存在客户端本地 `data/update.json`，接口不返回明文；如泄露，在 GitHub 撤销 Token 即可，无需重新发布。

> 想省去客户端填 Token 的麻烦？把仓库改为公开（当前含产品资料，不建议），
> 或把 exe 与版本清单托管到自己的服务器/网盘，在「更新检查地址」里填自定义 URL。
> 自定义地址格式需对齐 GitHub Releases API：返回 `tag_name`、`body`、`assets[]`。

## 四、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 检查更新报 401/403 | Token 无效或权限不足 | 重新生成 Token 并保存 |
| 检查更新报连接失败 | 电脑/手机无法访问 GitHub | 检查网络；必要时换自定义更新地址 |
| 显示已是最新版但实际有新版 | Release 的 tag 没带 `v` 或版本号没改 | 确认 `VERSION` 已改且 tag 为 `vX.Y.Z` |
| 下载链接是 Release 页面而非 exe | Release 没上传 `.exe` 资产 | 补传资产：`gh release upload v1.0.1 dist\AVAgent.exe` |
| 更新后数据丢失 | 新 exe 放在不同目录 | exe 与 `data/` 必须同目录，直接覆盖旧 exe 即可 |

## 五、版本策略建议

- **每次更新都提升一个小版本**（迭代更新）：任何功能新增、修复、文档更新发布时，
  都把 `VERSION` 的小版本 +1（如 1.0.1 → 1.0.2），并同步打 tag 发 Release。
  大改动才升中版本（1.x → 2.x）。这样客户端「检查更新」总能第一时间发现新版本。


- 功能新增/修复：小版本 `v1.0.x`；
- 模型提供商、模板、产品库属于数据，不随版本发布（存在 exe 同目录 `data/`），版本更新不影响已录入数据；
- 建议每次 Release 附上更新说明（`--notes`），客户端会直接展示前 2000 字符。
